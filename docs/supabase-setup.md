# ตั้งค่า Supabase สำหรับร้าน

แอปใช้ Supabase Auth สำหรับพนักงาน และบันทึกข้อมูลร้าน ออเดอร์ การรับเงิน กะเงินสด และประวัติใน Supabase ร้านใหม่ไม่มีเมนู โต๊ะ ออเดอร์ หรือยอดขายตั้งต้น เจ้าของใส่ชื่อร้านและเพิ่มข้อมูลจริงเมื่อเริ่มใช้งาน

## ติดตั้งฐานข้อมูล

1. เปิดโปรเจกต์ Supabase ของร้าน แล้วไปที่ **SQL Editor → New query**
2. คัดลอกไฟล์ `supabase/setup.sql` ทั้งหมดไปวาง แล้วกด **Run** ไฟล์นี้รวมโครงสร้างและฟังก์ชันทำงานของ POS
3. ตั้งค่า `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY` ใน `.env.local` ตาม `.env.example`
4. รัน `npm run check:supabase` เพื่อตรวจการเชื่อมต่อและเวอร์ชันฐานข้อมูล แล้วเริ่มแอปด้วย `npm start`

หากติดตั้งโครงสร้างรุ่นแรกไปแล้ว ให้รัน `supabase/upgrade.sql` ทั้งไฟล์ การติดตั้งไม่สร้างเมนู บัญชีพนักงาน หรือยอดขาย และไม่ล้างข้อมูลธุรกิจที่บันทึกไว้

## เข้าใช้บนเครื่องร้านโดยไม่กรอกบัญชี

1. รัน `npm run setup:device` เพื่อสร้างสิทธิ์ประจำเครื่องใน `.env.local` และไฟล์ `.local/device-setup.sql` ซึ่งมีเฉพาะค่าแฮชสำหรับลงทะเบียน
2. รัน `.local/device-setup.sql` ทั้งไฟล์ใน Supabase SQL Editor เพียงครั้งเดียว ไฟล์นี้เพิ่มระบบสิทธิ์เครื่องและผูกกับร้านเดิมของเจ้าของที่ยืนยันอีเมลแล้ว หากยังไม่มีร้าน ครั้งแรกแอปจะให้กรอกชื่อร้านและเริ่มว่าง
3. เริ่มแอปใหม่ด้วย `npm start` แล้วเปิด `http://127.0.0.1:5173/` บนเครื่องร้าน ไม่ต้องสมัครบัญชีหรือกรอกรหัสผ่าน

สิทธิ์นี้จำกัดเฉพาะทางเข้าบนคอมพิวเตอร์เครื่องนี้ ลูกค้ายังสแกน QR แล้วสั่งผ่าน Supabase ตามเดิม การเปิดจากเครื่องอื่นหรือเว็บไซต์ที่เผยแพร่ยังใช้บัญชีพนักงาน กุญแจสิทธิ์ไม่ถูกส่งไปใน JavaScript, QR หรือ Git และห้ามใส่ในตัวแปร `VITE_` หากต้องยกเลิกสิทธิ์เครื่อง ให้เปลี่ยน `enabled=false` ของเครื่องนั้นใน `private.pos_devices`

หากกลับมาใช้บัญชีภายหลัง บัญชีเจ้าของที่ยืนยันอีเมลตามที่กำหนดสามารถผูกกับร้านที่สร้างจากเครื่องนี้ได้ โดยเก็บเมนูและรายการเดิมไว้ จากนั้นนำ `POS_DEVICE_KEY` ออกจากสภาพแวดล้อมของเครื่องและเริ่มแอปใหม่เพื่อใช้หน้าเข้าสู่ระบบปกติ

## เริ่มใช้งานครั้งแรก

1. ลงชื่อเข้าใช้ด้วยบัญชีเจ้าของที่อนุญาตไว้ในฟังก์ชัน `pos_claim_owner` บัญชีต้องยืนยันอีเมลกับ Supabase Auth แล้ว
2. ใส่ชื่อร้านในแอป ระบบสร้างร้านว่างและสิทธิ์เจ้าของให้บัญชีนี้ บัญชีทั่วไปสร้างสิทธิ์เจ้าของเองไม่ได้
3. เพิ่มเมนูและราคาจริงใน **จัดการเมนู** แล้วเพิ่มโต๊ะใน **โต๊ะ & QR**
4. เปิดกะด้วยยอดเงินทอนที่นับได้ ก่อนรับเงินจากออเดอร์แรก

ให้พนักงานกดสร้างบัญชีในหน้าเข้าสู่ระบบและยืนยันอีเมลก่อน จากนั้นเจ้าของใส่อีเมลของพนักงานในหน้า **พนักงาน** ของแอป เลือกตำแหน่งผู้จัดการหรือแคชเชียร์ ระบบไม่ใช้ PIN ร่วมกัน เจ้าของและผู้ใช้ปัจจุบันไม่สามารถเปลี่ยนสิทธิ์หรือปิดบัญชีตนเองจากหน้านี้

## การทำรายการและสิทธิ์

- ข้อมูลทุกร้านแยกด้วย `restaurant_id` เปิด Row Level Security และตรวจสมาชิกที่ใช้งานได้ในการเรียกฟังก์ชันพนักงานทุกครั้ง
- ฟังก์ชันลูกค้าตรวจรหัสโต๊ะ เมนู ราคา ความพร้อม วิธีชำระ และคำขอซ้ำจากฐานข้อมูล ลูกค้ามีสิทธิ์ดูเฉพาะประวัติที่ผูกกับโทเค็นของเบราว์เซอร์ตนเอง
- พนักงานยืนยันรับเงินจริงก่อนพิมพ์ใบครัว การเรียกจากหน้าลูกค้าไม่สามารถยืนยันรับเงินหรือสั่งพิมพ์เองได้
- การปิดกะเก็บยอดคาดหมาย ยอดนับจริง และส่วนต่าง รายการอาหารในออเดอร์เก็บชื่อและราคาขณะสั่ง เพื่อไม่ให้การแก้เมนูเปลี่ยนประวัติ
- แอปแสดงความผิดพลาดเมื่อบันทึกไม่ได้และเก็บข้อมูลที่กรอกไว้ให้ลองใหม่ ไม่ใช้ข้อมูลธุรกิจในเครื่องแทนผลสำเร็จจากฐานข้อมูล

แคชเชียร์ตรวจยอดโอนและเงินสดด้วยตนเอง ระบบยังไม่ได้เชื่อมธนาคาร การเปิดหน้าพิมพ์ยืนยันได้เพียงว่ามีคำขอพิมพ์ จึงต้องตรวจเครื่องพิมพ์และกระดาษจริงด้วย

## การเผยแพร่และตรวจสอบ

- `.env.local` เก็บ URL และ publishable key และถูกยกเว้นจาก Git ค่านี้เป็นการตั้งค่าฝั่งเบราว์เซอร์ ห้ามใส่รหัสผ่านฐานข้อมูล `service_role` หรือ `sb_secret_...`
- `npm run check:supabase` เป็นการตรวจแบบอ่านอย่างเดียว ไม่ส่งออเดอร์ ไม่เปลี่ยนร้าน และไม่พิมพ์ใบครัว
- `npm test` และ `npm run build` ตรวจแอปบนเครื่อง ส่วน `npm run test:supabase-db` ต้องมี PostgreSQL บนเครื่อง (`pg_config`, `initdb`, `pg_ctl`, `psql`) หรือกำหนด `POS_TEST_PG_BIN` สคริปต์สร้างและลบฐานข้อมูลชั่วคราวบน Unix socket ของตัวเอง ไม่เชื่อมฐานข้อมูลร้าน
- เผยแพร่ `dist/` บน HTTPS hosting พร้อมค่าการเชื่อมต่อเดียวกัน แล้วสร้าง QR จากที่อยู่เว็บไซต์นั้น Supabase ไม่ได้เผยแพร่ localhost ออกสู่อินเทอร์เน็ต
- ทดสอบสแกน สั่งอาหาร รับเงิน พิมพ์ เสิร์ฟ และปิดกะข้ามอุปกรณ์ก่อนเปิดใช้กับลูกค้า

## รูปเมนูจากไฟล์และกล้อง

เพิ่มระบบรูปด้วย migration 5 (`supabase/menu-images-setup.sql` หลังติดตั้ง migration 4 แล้ว) หรือใช้ไฟล์รวม `.local/device-setup.sql` ที่สร้างใหม่ด้วย `npm run setup:device` บนเครื่องร้าน ไฟล์รวมเปิดสิทธิ์เครื่องและระบบรูปในครั้งเดียวโดยเก็บข้อมูลร้านเดิม

หน้าเพิ่มเมนูเลือกไฟล์จากเครื่องหรือเปิดกล้องได้ รูปแสดงให้ตรวจดูก่อนและอัปโหลดเมื่อกดบันทึก ระบบย่อเป็น WebP สูงสุด 1600 พิกเซล/2 MiB เก็บใน Supabase Storage ผู้ดูเมนูอ่านรูปได้ แต่สิทธิ์อัปโหลดออกให้เฉพาะเจ้าของ/ผู้จัดการหรือเครื่องร้านที่ยังมีสิทธิ์ โดยไม่อนุญาตเขียนทับหรือลบรูปเดิม หากอัปโหลดหรือบันทึกไม่สำเร็จ ฟอร์มยังเก็บข้อมูลและรูปให้ลองใหม่

## อัปเดตความถูกต้องของรายการ

หากติดตั้ง migrations 1–5 แล้ว ให้รัน `supabase/integrity-upgrade.sql` ทั้งไฟล์หนึ่งครั้ง ระบบเก็บร้านและรายการเดิม เพิ่มการกันเมนูซ้ำเมื่อลองบันทึกใหม่ รักษาสถานะหมด/ลบเมนู บันทึกจำนวนเงินและวิธีรับเงินในประวัติให้ถูกต้อง และเก็บเลขโต๊ะของบิลไว้แม้เปลี่ยนเลขโต๊ะภายหลัง หน้าบันทึกเมนูรอการอัปเดตนี้ก่อนส่งรายการ เพื่อไม่ให้กลับไปใช้พฤติกรรมเก่า

ประวัติเก่าที่ไม่เคยเก็บรายละเอียดจะยังอยู่ตามเดิม การเติมเลขโต๊ะให้บิลเดิมใช้เลขที่ทราบในวันที่อัปเดต ไม่อ้างว่าสามารถกู้ข้อมูลในอดีตที่ไม่ได้บันทึกไว้ได้
